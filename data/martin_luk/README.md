# Martin Luk — Trading Knowledge Base

A structured archive of Martin Luk's trading philosophy, livestream transcripts, and
actual/observed trades. Long-term goal: generate trade suggestions that follow his
methodology.

Channel: `martinlukkt` (YouTube) — discretionary momentum/swing trader in the
Qullamaggie / Minervini / O'Neil lineage (Stage-2 leaders, EMA pullbacks, episodic
pivots, tight risk).

## How this relates to the existing Luk tooling

This folder is the **raw knowledge base**. It is separate from, but feeds, the existing
pipeline:

| Existing | Purpose |
|----------|---------|
| `data/luk_notes.jsonl` + `add_luk_note.py` | Discrete dated observations (one pick/comment each) |
| `run_luk_analyzer.py` → `data/studies/luk_patterns.md` | Reverse-engineers the technical setup behind each observation, synthesizes screener rules |

Flow: **raw transcripts (here)** → distilled `principles.md` + extracted `observed_trades.jsonl`
→ (optionally) seed `luk_notes.jsonl` → analyzer → screener rules → trade suggestions.

## Layout

```
INVENTORY.md                    High-level table of EVERY channel video + status
                                (✅ ingested / ⚠️ captions unavailable). GENERATED — rerun
                                build_luk_inventory.py to refresh; don't hand-edit.
ambiguous_tickers.md            "Homework", grouped by video w/ clickable YouTube timestamp
                                links: (1) garbled/unclear tickers to confirm, and (2) a
                                trades table w/ fill dates — ⬜ flags rows needing a glance
                                (? ticker, unresolved date, or a date inferred to a different
                                day). GENERATED by build_luk_extracts.py.
philosophy/principles.md        Synthesized rules, by category, each cited to <video_dir>@<mm:ss>
                                with a support tally. GENERATED (synthesis of principles_raw).
philosophy/principles_raw.jsonl Flattened per-video principles (input to the synthesis).
videos/<type>/<YYYY-MM-DD>_<videoId>/  One folder per video, by category, keyed on STREAM date.
    transcript.txt              Raw timestamped transcript (auto-captions, deduped).
    meta.json                   url, ids, title, channel, stream_date, capture details.
    notes.md                    Supplemental human notes: screen actions, ticker fixes,
                                anything inaudible. This is where Gabe adds context later.
    auto_extract.json           Per-video structured extract (trades/principles/ambiguous
                                tickers) mined from the transcript. Source for the aggregates.
videos/livestreams/_channel_streams.tsv  Manifest of all channel streams (id\ttitle);
                                source of truth for the inventory's "what exists" list.
trades/observed_trades.jsonl    One JSON object per line = one actual/observed trade.
                                GENERATED from all auto_extract.json by build_luk_extracts.py.
```

As of the initial backfill: **59** channel streams, **52** ingested, **7** with no
auto-captions (YouTube never generated them). See `INVENTORY.md` for the live breakdown.

### Video categories (`<type>`)
Videos are grouped by kind under `videos/`:
- `livestreams/` — live trading streams (default).
- `interviews/` — interviews, podcasts, guest appearances.
Add more categories as needed; `add_luk_video.py --type <name>` files into `videos/<name>/`.

### Video folder naming
`videos/<type>/<stream_date>_<video_id>/` — e.g. `videos/livestreams/2026-06-23_Z2PyXDLCRaM/`.
`stream_date` is the YouTube **upload_date** (the day he streamed), NOT the capture date.
Folder names (`<date>_<id>`) are unique, so `source` citations in `principles.md` /
`observed_trades.jsonl` reference just `<date>_<id>@<mm:ss>` regardless of category.

### `observed_trades.jsonl` schema (one object per line)
GENERATED from the per-video `auto_extract.json` by `build_luk_extracts.py` — do not
hand-edit; edit the `auto_extract.json` and rebuild.
```json
{
  "date": "2026-01-08",            // STREAM date (when he discussed it), NOT the fill date
  "ticker": "IONQ",                // resolved symbol, or "?" when the caption is too garbled
  "direction": "long",             // long | short
  "action": "entry",               // entry | add | trim | exit | stopped_out | reentry | hold
  "setup": "weekly EMA pullback within base",  // his stated rationale, short
  "entry_basis": "1-min breakout", // trigger if stated
  "stop": "",                      // stop rule if stated
  "source": "2026-01-08_IgiOMLGVD_A@75:27",  // video_dir@mm:ss
  "confidence": "stated",          // stated | inferred  (did HE say it, or did we infer?)
  "fill_timing": "2025-12-17",     // raw timing phrase: today|yesterday|<weekday>|YYYY-MM-DD|last week|""
  "fill_date": "2025-12-17",       // fill_timing RESOLVED to ISO via stream date; "" if unresolvable
  "notes": ""
}
```
- **`date` is the stream date, not the fill date.** Many trades are recaps ("I bought it
  Thursday", "shorted on the 17th of December"). `fill_timing` captures his words; `fill_date`
  resolves them deterministically (real date math, weekends skipped). Use `fill_date` for any
  time-based analysis — but it's a best-effort inference, not a broker record.
- **`ticker: "?"`** = the caption was too garbled to resolve confidently; every `?` (and every
  interpreted-guess symbol) also appears in `ambiguous_tickers.md` for human confirmation.
- **`confidence: inferred`** = deduced from narration vs. explicitly stated.
- The trade list was **verified against transcripts** (a per-video pass that drops watchlist-only
  names, strips unsupported numbers, and demotes shaky tickers) — but it remains an
  auto-extraction; survivorship/narration bias is the standing risk.

## Adding a new video

One command (fetches metadata + auto-captions, dedupes, scaffolds the folder):
```bash
.venv/bin/python3 add_luk_video.py <URL>                 # → videos/livestreams/<date>_<id>/
.venv/bin/python3 add_luk_video.py <URL> --type interviews
```
Then fill in the `notes.md` ticker table and distill into `philosophy/principles.md`.
(`add_luk_video.py` lives at the repo root; yt-dlp is installed in `.venv`.)

After adding (or to re-pull the channel list and refresh status), rebuild the inventory:
```bash
.venv/bin/yt-dlp --flat-playlist --skip-download --print "%(id)s\t%(title)s" \
  "https://www.youtube.com/@martinlukkt/streams" > data/martin_luk/videos/livestreams/_channel_streams.tsv
.venv/bin/python3 build_luk_inventory.py        # --no-network to skip caption checks
```

## Caveats
- **Auto-captions misread tickers constantly** (e.g. "I want Q" = IONQ, "fraud"/"crowd" =
  CRWD, "Iron" = IREN). Treat every ticker as tentative until confirmed against the screen.
  Corrections go in each video's `notes.md`.
- He is **discretionary** — principles are tendencies, not mechanical rules. Validate any
  generated suggestion against actual price action before acting.
